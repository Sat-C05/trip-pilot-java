# TripPilot frontend

React/TypeScript planning workspace with session authentication, saved plans, requirements/clarification, up to three explicit destination cards, live progress/cancellation, comparison, selected-trip contexts and fresh scoped follow-ups. Validated records supply factual content; citations, timestamps, estimates, gaps/conflicts/stale fields and source-image attribution remain visible. Commercial quotes/inventory remain unavailable. Selected trips include an explicitly labeled optional booking demonstration with provider inventory/quotes, bounded consent/authorization, submit/revoke, durable confirmation and uncertainty/status checks; disabled by default. See [booking setup and boundaries](../docs/phase5-booking.md).

Run `npm ci` then `npm run dev`. Vite forwards `/api` and `/actuator/health` to `http://127.0.0.1:8002`; override with BACKEND_URL. Backend/MySQL and the dedicated local model must be configured as in the root README. Start/restart the backend for V8/card-management routes while preserving data. Sign up in the browser (minimum 12-character password), enter Indian destinations, research, compare and select a supported trip. Each selected trip has its own requirements/history/research.

Current full verification is `scripts/verify-phase5.ps1`: 102 backend + 8 provider tests with no failures/errors/skips, full production build and planning/card CRUD/Inspector/booking browser checks, live research and packaged smoke. Booking browser covers consent, quote-bound authorization, submission, durable confirmation/reload and mobile layout against a real separate provider; no browser API stubs.

`npm run build` checks TypeScript and builds production assets. `scripts/verify-phase4.ps1` additionally verifies actual browser flows on production assets and an isolated real-MySQL backend, as well as internet/local-model regression. See [planning behavior, API and limitations](../docs/phase4-planning.md). Browser checks cover desktop/mobile, auth/logout, comparison, independent selected contexts, follow-up/cancellation/reload and explicit clarification. Production assets require a same-origin backend reverse proxy for `/api`; the local Vite development proxy supplies this during development.

Research Inspector on each card links saved task/event metadata to exact evidence passages, validation decisions and captured model/budget settings; supports manual refresh, retained event pagination and desktop/mobile layouts. Raw model/personal prompts are excluded. See ../docs/phase6-delivery.md.


The refreshed workspace adds searchable card summaries, editable titles/personal notes, persistent Trash/restore and plan renaming. See [card CRUD](../docs/card-management.md) and [hosting recommendations](../docs/hosting-options.md). Evidence and selected/booking records stay separate from personal notes.
